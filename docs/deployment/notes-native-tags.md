# Notes 原生标签修复（F103/F104）

此前的 `tagsPreserved` 只检查正文字符，不证明原生标签成功。历史脚本字段已改为 `tagTextPreserved`；旧结果不能作为原生标签验收证据。

## 行为

- 写入 #O1、#KR1、#KR2 等目标标识后，通过 Notes 原生编辑器完成标签输入。每篇笔记中同名标识至少有一处成为原生标签，日志中其余重复引用保留正文。
- 读回包含真实标签名称和原位置。Apple 脚本接口会把原生标签读成占位符，不能直接拿其 HTML 覆盖已有内容。
- 追加保留已有标签；定稿更新使用新稿的 O/KR 标签，其他已有原生标签（例如用户的 #OK1）保留。未知附件、共享、锁定笔记拒绝操作。
- 标签未完成时不会把正文保存成功当作整个操作完成。先核对/补齐标签，再恢复原事件，不重复追加正文或创建笔记。

## 本机依赖与限制

需要 macOS 登录桌面、Apple Notes、Swift 命令行工具、Automation 和辅助功能权限。此实现会显示目标笔记；写入会使用编辑器和暂存剪贴板，正常结束后恢复剪贴板（用户期间修改则不覆盖；进程被强制终止时可能留下临时剪贴板内容）。运行期间不要在 Notes 中并行输入或切换笔记。它不是已验收的无人值守后台接口；尚未部署到飞书网关。

按真实账户、文件夹、笔记 ID 定位；界面正文与脚本快照一致才继续。界面访问串行，跨进程锁位于系统临时目录 `pgtd-notes-ui-<uid>.lock`。崩溃遗留锁需先核对其中 PID 和外部笔记结果，再清理锁；不能盲目换目录/重投。每次桥接默认总超时60秒，正文65536 UTF-16单位、原生 HTML 131072单位、最多512个标题、最多32种待处理标签、最多512个已有原生标签对象；超出或界面不匹配会停止。标签标识按独立的 #O数字/#KR数字识别，后接空格或换行。

快照已改为包含标签的规范化 HTML；升级前尚未确认的旧草案可能因快照变化被拒绝，需要重新读回讨论生成草案。历史未完成操作必须先核对，不直接重放。

## 验证

```bash
npm run verify:notes-tags -- --write-synthetic
# 只修复现有两篇合成笔记的标签，不追加测试正文
npm run verify:notes-tags -- --write-synthetic --repair-only
```

脚本使用 F104 私有状态中的现有两篇笔记，不创建第三篇；正文包含合成标记才允许写入。首次追加一段固定标记的测试内容，后续复用；验证原生对象、标签原文、追加、整篇替换、用户标签保留、重复确保和过期快照拒绝。不会调用模型或发送飞书。

2026-09-27 真实验证：

- 修复前：最新稿 AX 原生对象 O1=false、KR1=false、OK1=true。
- 修复后：最新稿 O1/KR1/KR2/OK1 均为原生对象；追加与再次替换后读回一致。完整验证约14–21秒（多次桥接总耗时），无模型调用。
- 日志 O1/KR1/KR2 均为原生对象；标签修复约4.8秒。
- 独立人工界面自动操作：点击侧栏 O1，窗口显示“#O1 – 1个备忘录”，Notes selection 返回的真实 ID 与合成最新稿一致（日志补标签之前测量）。这项侧栏证据与脚本检查分开记录，脚本不虚报自动完成筛选。

尚未测：Notes 退出重启、多设备同步、网关进程权限、锁屏运行。原生提醒事项按标签自动查询及 Review 业务仍属于后续任务。
