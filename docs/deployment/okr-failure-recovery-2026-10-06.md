# OKR 分析失败回执与恢复

基准0d75bef；用户要求读取飞书并说明反复“未完成”的具体原因和恢复步骤。原生飞书UI核验：前次补充成功标准已返回已记录，随后“作为独立的O”返回泛化失败提示。私人正文和真实ID不提交Git。

只读核验最新okr analysis为MODEL_TIMEOUT，usage第73次failed/network_or_timeout，15029.65ms，用量/费用未结算，沿用原保守预算预留；前次第71次invalid_output，72次done。pending/publication均无，原回答已保存而失败轮未推进草案。不同故障被模型适配器和会话回执泛化，用户无法自行判断保存状态或恢复操作。旧输出校验失败的具体字段没有日志证据，不能倒推根因。

修复范围：模型仅传播白名单原因并在账本保存安全failureCode，不保存模型返回正文；回执说明保存状态、未更新范围、原因及恢复步骤。超时、服务连接/限流/鉴权、用量/预算、输出校验、阶段/结构和单项约束均有对应说明，未知如实说明。时限/次数/费用上限不变，鉴权/预算等需维护者先处理。

回复原失败回执“重试分析”以新消息重试，复用原已保存回答和当前草案。须精确匹配同身份同会话的已保存失败事件，并验证直接父回执也是失败；成功回执和未关联请求均不调用模型。原失败消息不重跑，重试事件重复/跨重启不重复调用。历史失败回执可定位原来源，二次失败可继续通过新的关联消息显式重试；每条新重试至多一轮，仍受共享预算限制。日志记录重试指令及原回答来源，不替用户确认定稿。Notes未知结果核对仍优先。

TDD公开模型/可信飞书边界先红：invalid JSON不能传播可核实原因，超时回执不说明原因和恢复步骤。修复后超时保存/原回答复用/重启去重/错误来源拒绝及安全原因回归通过。受影响88项通过，完整241项通过，npm run check及git diff --check通过。单agent顺序审查规范与需求：核对身份、来源指纹、父失败状态、旧状态兼容、预算/去重、日志归属、私人错误不泄露和业务写入保护。开发测试零付费调用。

部署和真实用户重试另行记录；本地合成通过不代表实际模型质量通过，也不保证服务不再超时。没有自动重投原飞书事件或主动发送消息。
