# 首版任务拆分草案

依据：[已确认规格](spec.md)。状态：用户已确认粒度与依赖；已发布为 issues/ 下六个独立任务。

各项均通过已确认的“消息事件 → 用户回执和 Apple 边界可见状态”验收。一次只实施一个任务，不并行开发。不按数据库、模型、UI 等技术层分别交付。

执行状态：任务 01 已完成本地模拟验收；任务 02 为下一项，03–06 等待依赖完成。各任务状态以 issues/ 下独立文件为准。

## 01：本地明确指令收集演示

**Blocked by:** None

**交付：** 输入一条本地合成消息，模拟创建 Inbox 和其中一条事项，输出可见回执及事项内容。建立真实可运行的开发入口、测试和示例命令，明确标记为模拟。

**输入输出：** 规范化文字事件和本地激活词配置 → 未处理、待确认、已收集或分析未完成等结果，以及模拟列表/事项状态。

**验收：**

- [ ] 默认激活词“小婕 GTD”可通过本地配置修改；未激活新消息不写入。
- [ ] 明确“收集/记录”指令创建一条，原文完整保留，正常分析时备注有一句“小婕的建议：……”。
- [ ] 模拟 Inbox 缺失时创建列表；成功结果含模拟服务实际返回的稳定对象 ID。
- [ ] 文章链接只保存；裸链接先询问，通过明确关联的确认回复创建一次；讨论文章不收集。
- [ ] 明确收集意图下模拟分析失败仍保存原文，回执注明分析未完成。
- [ ] 不支持的消息明确提示；需要提醒或其他尚未实现的能力明确说明，不能声称已完成。
- [ ] 合成演示和行为测试实际运行；模型与 Apple 使用外部边界替身，不能声称真实集成或模型质量通过。

**真实依赖：** 本地开发运行时与文件系统；不需要飞书、Apple 数据或模型凭据。具体技术栈实施时选定并记录用途，优先少依赖。

## 02：提醒时间与澄清更新

**Blocked by:** 01

**交付：** 从本地消息创建带提醒时间的模拟事项；时间不清时先收集，用户回复后更新同一条。保留 01 的收集演示。

**验收：**

- [ ] 明确时间设置在同一条 Inbox 事项上；默认 Asia/Shanghai 可配置，显式时区优先。
- [ ] 相对日期基于原消息发送时间；跨日处理或重投不漂移。
- [ ] 不明确时间先收集，再追问；回复无需激活词，只更新明确关联的事项。
- [ ] 多个待澄清项、跨用户或跨会话回复不能误更新；无法唯一关联时先询问。
- [ ] 回执区分已收集、待补时间、提醒设置成功和设置失败。
- [ ] 模拟时间分析只验证流程，真实模型的时间理解留给 05。

**真实依赖：** 01 的公开处理入口和外部边界替身。过去时间等尚未冻结语义在出现具体样例时澄清，不自行顺延。

## 03：重复投递、部分成功与重启恢复

**Blocked by:** 02

**交付：** 对 01、02 的完整路径注入重复投递、响应丢失和进程重启，演示最终只产生一个事项并保持准确回执。

**验收：**

- [ ] 同一事件重复或并发投递不会重复创建；不同事件不能只因标题相同被合并。
- [ ] 列表/事项创建或时间更新结果未知时先查询外部状态，无法核实就停止新增写入。
- [ ] Apple 成功但回执失败时，恢复只补回执；事项已创建但时间失败时，只修复原事项。
- [ ] 最小操作记录和待澄清关联可在重启后恢复；不维护另一套任务事实源。
- [ ] 调用、输入输出、超时和重试都有可配置上限；超限不静默截断原文，耗尽预算保存进度。
- [ ] 用独立进程的合成故障演示验证恢复；日志不含私人正文。

**真实依赖：** 本地持久化与可控外部服务替身；核对过程的模拟能力在 04 对真实 Apple 接口再次验证。

## 04：真实 Apple 收集和提醒

**Blocked by:** 03

**交付：** 本地合成消息实际写入选定 Apple Inbox，返回真实 ID，并可在 Apple 查看原文、建议和提醒。保持模拟模式可运行。

**验收：**

- [ ] 调查并选定可用 Apple 接入，记录实际限制、账户与目标列表的绑定方式。
- [ ] 在相应授权和系统权限具备后，用合成数据验证缺失列表创建、条目创建和更新时间。
- [ ] 多同名列表不能随意选择；后续操作使用实际返回 ID。
- [ ] 实测原文容量、提醒字段及外部状态核对能力；能力不足需先修正规格/方案，不以模拟通过代替。
- [ ] 实际提醒通知与字段写入分别验收；Apple 权限拒绝和部分成功回执准确。
- [ ] 演示用户手动将资料条目移动到 Wiki 待处理列表，不自动归档 Wiki。

**真实依赖：** macOS Apple 接入工具、选定账户/列表、系统权限；读取范围与真实测试授权需具体落实。模型仍可用明确标记的替身。

## 05：真实模型分析与降级

**Blocked by:** 03

**交付：** 本地合成消息经真实模型分析后，在模拟 Apple 边界生成事项和回执；输出一句署名建议，时间澄清及降级仍有效。

**验收：**

- [ ] 确认实际供应商、模型、凭据接入方式及价格来源；凭据不进入仓库或日志。
- [ ] 使用合成样例单独评估收集/讨论区分、时间抽取与一句话建议，报告错误样例。
- [ ] 结构化分析结果经代码校验，不能控制权限、绕过激活或直接写入 Apple。
- [ ] 超时、无效输出和预算耗尽走已确认的降级路径，明确收集原文可保留。
- [ ] 固定模型调用数、输入输出和超时上限；记录实际 token、延迟、失败原因和可核实费用。
- [ ] 价格与金额预算落实后才执行真实付费评估；不把工程候选值称为实测结论。

**真实依赖：** 已配置并授权使用的模型服务及预算。03 的持久化与预算控制；不依赖 04 的真实 Apple 接入，因此不添加虚假依赖。

## 06：飞书到 Apple 的真实闭环与首版验收

**Blocked by:** 04、05

**交付：** 用户在授权的飞书入口发送指令，实际创建或更新 Apple 事项并收到准确回执。

**验收：**

- [ ] 验证已安装 OpenClaw/飞书插件支持的接入方式、消息 ID、回复关联及身份验证；授权边界由代码执行。
- [ ] 正常收集、文章链接、提醒、澄清回复和未激活消息均按规格表现；不支持的类型明确提示。
- [ ] 原文保留，Apple ID 可定位；重复投递、回执失败和重启不制造重复条目。
- [ ] 真实测量完整链路容量和延迟，固定最终预算并报告模型质量及未验证限制。
- [ ] 实际执行适用完整检查、启动和运行示例；顺序完成规范/需求审查，处理阻塞发现。
- [ ] 首版全部验收项依据真实证据勾选，记录提交和同步结果。

**真实依赖：** 可用 OpenClaw/飞书连接、允许的用户与会话配置、04 的 Apple 接入、05 的模型接入，以及对应部署和发送授权。

## 执行约定

- 建议按 01 → 02 → 03 → 04 → 05 → 06 顺序执行，默认单 agent；依赖图中 04 与 05 可以独立推进，但不因此启用并行。
- 获得任务拆分确认后，按本地 tracker 规范发布 6 个独立任务文件，分别维护 State、Verification 与验收清单。
- 每次只实施一个可验收任务，相关测试及演示通过、审查完成后再标记 done 并保留版本提交。
- 首个任务不需要等待外部账户连接；最终首版完成必须经过 06 的真实验收。
