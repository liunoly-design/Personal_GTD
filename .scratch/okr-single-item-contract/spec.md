# OKR 单项更新合同与空行误判修复

State: done
基准：`b27999e8177943c576db862813687245e5b69ebc`。

## 问题与范围

用户明确只想完善当前目标的 KR，仍连续收到 MULTIPLE_OKR_ITEMS。上一轮增加提示词及错误说明不足以稳定实现每轮一项：模型仍输出整个稿件，会顺手重写现有 O 或增加多个 KR；解析器还把项末分隔空行的变化计为另一项修改。

本任务只实现已有工作草案的单项模型输出合同，保留未修改条目、周期、KR 父节点和草案确认规则；空行误判按项末空白归一比较。原稿及原输入不在比较前改写。没有工作草案时继续原有初始 O 输出合同。

## 输入与输出

已有 workingDraft 时，模型输出 stage/summary/advice/questions 和唯一 change 对象或 null。change 指定 upsert/delete、唯一标签 ID、KR 的既有父 O ID、该项标题与正文。代码将这一项组装到既有完整稿中，返回原处理器所需 draft。只讨论时 change=null，保留原稿；不能包含完整 draft、数组、第二条变更或多项标题。

保留旧模型会话、日志、笔记与预算布局，无迁移；旧缓存输出仍按旧逻辑复用。原文记录、同消息去重、确认版本与外部写入恢复不变。已有草案分支保留原周期，不在该分支用全稿生成顺带修改周期；周期重新设定应另行明确，不能暗中变化。

## 失败、预算与验证边界

非法 ID、父节点变化、含子项的 O 删除、最后一个 O 删除、单项内嵌多个标题、O 未满三个 KR 就新增下一个 O 均拒绝；原回答仍按既有失败路径保存，不自动补写另一项或额外调用模型。保持每事件一次调用、现有输入/输出、超时和共享费用上限。
