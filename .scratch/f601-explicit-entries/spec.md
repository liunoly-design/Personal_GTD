## Problem Statement

目前用户要用“小婕 gtd okr 讨论”启动 OKR，入口仍嵌在 GTD 激活词下。需要三个平级、明确的命名空间：`小婕 gtd XXX`、`小婕 okr XXX`、`小婕 review XXX`，使收集、规划、复盘不互相误处理。

## Solution 与本次范围

后续 Grill Q34–Q37 已确认，见[记录](../../OS_WIKI/需求Grill确认记录.md)：三个模块首个可用版都要基本查询；意图明确的查询/讨论/复盘可自动转交，复合请求顺序处理。F601/T01 是明确入口切片，完整查询、自由意图分派与组合分别在相邻任务交付，不冒充独立模块首版完成。

交付一条完整可信文字入口路径：识别平级入口 → 核对原消息 → 选择模块与已支持动作 → 调用现有流程或返回准确能力提示 → 关联回执/续接 → 去重与恢复。

本次是显式入口解析和执行路由，不要求模型猜测模块，不创建独立 Agent 配置或实现 Review 主体。GTD/OKR 已有行为复用；Review 能识别但尚无业务实现时返回“Review 功能尚未启用/实现”，不保存到 Inbox、不调用模型、不写 Notes。

Q38–Q41 已确认[执行与语义边界](../../OS_WIKI/需求Grill确认记录.md)：后续自由表达可以一次预算内模型识别，单项操作与复合失败规则分别落实到对应动作/编排任务。本确定性入口切片仍零路由模型调用，不因全局需求确认加入全部组合能力。

三个独立模块/Agent 的实际组装和独立安装仍由后续切片推进；本任务不能以三个关键词可识别宣称独立 Agent 已部署。

## User Stories

1. 我用“小婕 gtd 买牛奶”继续收集，不需要改变既有习惯。
2. 我用“小婕 okr 讨论”直接启动 OKR，不必经过 GTD 子命令。
3. 我用“小婕 review 日复盘”明确选择 Review，未提供能力时获得准确说明，而不是多一条任务。
4. 回复现有讨论/澄清回执时我不用重复前缀，仍关联原模块、原事项与当前草案。
5. 旧 OKR 指令和旧日志仍可恢复，不因为入口变化重复分析或重复写入。

## 入口规则

- 默认形式为 `小婕 <gtd|okr|review> <动作或流程> [参数]`；XXX 表示处理动作或启动流程，参数承载对象、内容、范围、目的。GTD 省略动作仍按已确认默认收集兼容。英文模块名大小写不敏感，前导空白与词间零个/多个空格沿用已有兼容。
- 目标目录见[动作与流程入口](../../OS_WIKI/三个Agent动作与流程入口.md)，区分已有业务基础与待开发能力。本切片范围不因目录新增条目扩大。
- 模块名之后需要空白、中文/英文逗号、中文/英文冒号或消息结束；不识别 `小婕 okrx`、`小婕 reviewable`。
- 接受 `小婕GTD，买牛奶`、`小婕 OKR：讨论`、`小婕review 日复盘`；引用/正文中出现前缀不当作新入口。
- 明确入口优先于回复关系：回复旧 GTD 回执但以“小婕 okr 讨论”开头，作为新 OKR 请求。无前缀回复必须关联同用户/同会话的已知请求，不猜“最近一次”。
- 单独“小婕”不进入任何模块；仅模块前缀按该模块返回帮助/补内容提示，不写空对象。
- 现有 `activation` 自定义配置继续有效，仍为 GTD 兼容入口；不能改字段语义或覆盖旧配置。新增显式入口与自定义词出现不同模块歧义时，启动校验拒绝冲突配置并说明；同属 GTD 的重合允许。
- 是否以后允许自定义 OKR/Review 前缀不在本任务；本次默认平级形式不要求新配置字段。

## 模块与动作

补充需求：每个模块支持查询与同义表达，目录见[查询与同义规则](../../OS_WIKI/三个Agent动作与流程入口.md)。本任务适配已有收集、提醒、OKR 讨论/记录/续接的明确等义表达，并准确识别查询等保留动作后报告尚未实现；实际查询数据能力和自由模型意图分析分别在后续任务交付，不增加路由模型调用。

实现时记录明确同义样例及反例，按模块、对象、上下文区分动作和待记录内容。否定/引用/已识别未支持操作不能因默认收集而误写；保留原文作为记录与冲突核对依据。“好的/继续”等普通应答不等同于确认定稿。

| 入口 | 本次已接入动作 | 未实现行为 |
| --- | --- | --- |
| `小婕 gtd XXX` | 默认正文收集、显式收集/记录、提醒、关联补时间、裸链接确认 | 不在本任务增加查询/移动/完成/日历；已识别为尚未支持的维护命令返回说明，不能声称已执行 |
| `小婕 okr XXX` | 讨论/续接、记录正文、暂停、确认定稿；关联回复沿用现有会话 | 优先级规划和新计划执行不在本任务；未知 OKR 动作提示帮助，不降级到 GTD |
| `小婕 review XXX` | 命名空间识别、空入口帮助、未启用/未实现状态 | 日/周/专题、注册等动作只是未来表达示例，本次不启动讨论或定时任务 |

GTD 默认收集规则继续成立：普通正文可以是“完成一份报告”之类任务内容。只有明确操作句式（例如“完成任务：<对象>”“查询任务”“新建日程：...”）被确定性识别为未支持动作时才返回能力提示；不因正文含某个动词就阻止收集。实现时为这些句式写独立样例，不把通用自然语言动作识别扩进本任务。

### 旧 OKR 兼容

`小婕 gtd okr 讨论/续接/记录/暂停/确认定稿` 保留为别名，路由到同一个 OKR 业务处理器。新入口使用同一私有配置、笔记绑定、会话和草案版本，不复制数据库、不新建另一组笔记。

旧兼容别名是这一切片的显式例外，不把“小婕 gtd review ...”升级为另一个 Review 别名。一个 GTD 收集正文中普通提到 OKR/复盘也不自动跨模块。

## 输入输出与测试接口

沿用公开边界：规范化可信事件/`reply_dispatch` → 飞书原消息读取 → 路由 → 用户可见回执 + Apple/Notes 边界状态。

保留原始正文、事件 ID、发送时间、用户、会话与回复元数据，用单独解析结果表达模块/动作/正文范围；不能重写原事件正文再做冲突摘要，也不能为不同入口生成新事件 ID。内部解析字段名由实现决定。

输出至少区分：未处理、需内容/帮助、模块不可用、已调用业务后的实际状态、来源无效、失败、结果未知。Review 不可用和 OKR 未配置均不落入 GTD。回执可靠性沿用现有飞书去重与未知结果处理。

路由标签应覆盖 gtd/okr/review，并兼容旧日志中未保存 gtd 标签的收集事件。新旧 OKR 回执都绑定 OKR 和原草案版本；显式“确认定稿”没有当前草案关联时仍不能写入。

## 权限与 Failure Handling

- 本地上下文只筛选候选，原消息 ID、身份、会话、正文及更新状态按现有可信规则核验；不能扩大允许发送者或会话范围。
- 当前 OKR 普通关联回复的更新标记核对规则继续保留，不把例外扩展为所有编辑消息都能执行。
- 精确入口在插件中 handled 后，主 Agent 不再次调用同一操作；Review 不可用也算已答复，不能流入宿主后自动再收集。
- 未知动作、未配置模块、空指令不新增模型/Apple 调用。
- 同事件重复投递复用业务结果，ID 内容冲突按既有规则拒绝；不可用回执重放也不得重复发送。
- 外部写入/回执超时未知先核对；已有事项、笔记和提醒 ID 恢复不变。
- 无关联时间回复沿用现有保守候选与目标提示，不扩展到 OKR/Review 猜测。

## Testing Decisions 与验收样例

关键行为逐项 TDD，使用可信事件公开入口和模拟外部 HTTP/Apple/Notes 边界，不模拟内部函数来复述实现。可测试小解析入口的前缀边界，但最终分派必须通过完整行为验证。

| 合成输入/场景 | 可观察预期 |
| --- | --- |
| `小婕 gtd 买牛奶` | 创建一个 Inbox 项，保持默认收集 |
| `小婕GTD，提醒我明天下午三点交报价` | 按发送时间处理，更新同一事项 |
| `小婕 okr 讨论` | 启动已有 OKR 文档路径；Inbox 不增项 |
| `小婕 OKR：记录：合成回答` | 保存 OKR 记录；不走收集 |
| `小婕 gtd okr 讨论` | 同一 OKR 配置/会话别名，行为与新入口一致 |
| `小婕 okr` / `小婕 okr 未知动作` | 帮助提示，不创建任务/笔记 |
| `小婕 review 日复盘` / `小婕 review 注册周复盘` | 明确尚未启用/实现，不读取任务或调用模型 |
| `小婕 review` | 帮助和当前可用性说明 |
| 新/旧 OKR 回执的关联回答 | 同一 OKR 请求续接，不误入 GTD |
| 回复 GTD 回执但写 `小婕 okr 讨论` | 新 OKR 请求，原 GTD 事项不变 |
| 关联当前草案“确认定稿” / 旧草案确认 | 前者按原规则写入，后者拒绝；确认不重新生成 |
| 引用前缀、`小婕 okrx`、`小婕 reviewable` | 未处理，不作为有效模块入口 |
| 仅 GTD 配置收到 OKR/Review | 准确不可用回执，不进入 Inbox、不初始化缺失能力 |
| 重投、响应丢失、重启恢复 | 同一事件不重复写业务对象或回执，旧状态可继续 |
| 自定义 GTD 激活词 | 旧行为保留，新默认 OKR/Review 仍可识别；冲突配置明确拒绝 |

验收步骤：

- [x] 新样例逐项先失败后通过，旧 capture/OKR/飞书/插件/恢复测试仍通过。
- [x] 运行三个平级入口的合成演示，包含未启用 Review 和旧 OKR 别名。
- [x] 使用原私有状态布局的合成 fixture/新进程证明旧请求续接与恢复，不读取私人数据库。
- [x] 执行 `npm run check`、`npm test` 及受影响现有示例；新增演示命令实现后再写 README。
- [x] 顺序检查规范/需求，更新本任务 Verification；没有真实部署授权或实测时明确标未部署。

新增演示固定合成时钟与同一状态目录，覆盖上述分派/边界/恢复样例；记录数量、耗时及失败。端到端真实延迟目标待测，不能把字符串解析速度代替业务链路速度。不运行付费模型或真实外部写入来验证入口规则。
