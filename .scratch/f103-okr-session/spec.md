# F103：OKR 记录与续接

基准：`8b4c5cb6fb02a2975483fa8a7c13b0affa96b022`。

## 本次完整路径

飞书可信来源 → `小婕 gtd okr 讨论` → 创建或读回固定的 OKR 日志 → 回复回执保存原文 → 暂停、重启、再次启动后继续。使用一篇日志；F104 定稿时再实现第二篇最新完整稿，始终最多两篇。标签如 #O1、#KR1 原样留在目标/KR 文本中，后续 Review 使用同名标签关联事项。

- 显式 `小婕 gtd okr 记录：内容` 可保存；普通消息只有回复已关联的 OKR 回执/原消息才进入讨论。`小婕 gtd okr 暂停` 停止记录，重新“讨论”恢复。
- 新记录回执提示先提供个人情况与目标；已有记录展示最近记录并允许续接。本次只保存用户原文，不把讨论草案自动视为定稿或创建事项。
- OKR 未配置、失败或不支持的 OKR 子命令均不会落入 Inbox。
- 真实接入依赖已授权 Notes 位置、系统自动化权限、飞书原消息读取与发送；运行配置显式启用，开发不自动部署/发送。

## 输入输出与测试接口

业务接口 `openOkrSession(...).handle({id,senderId,conversationId,action,text,sentAt})`，action 为 open/record/pause；返回状态、noteId（如有）、中文回执。外部边界为 Notes bridge；飞书通过现有 `openFeishuCapture.handle` 验证路由、身份及回执。按 AGENTS 约定在此确定测试接口，逐项 TDD。

## 失败与恢复

- 真实笔记 ID 持久化；位置变更、笔记丢失、读回不符停止，不按标题创建替代笔记。
- 写前记录操作意图；同一来源重投不重复追加。创建/追加超时后先查标记；未核实时停止新增写入，不盲目重试。新进程可核对已落地写入。
- 追加前比较已读 HTML 快照，保留人工内容；Notes 没有原子条件更新，多设备同时编辑仍有竞态，未声称解决。
- 串行处理及跨进程状态占用保护；飞书回执沿用既有去重与未知结果处理。

## 预算与验收

每条输入最多 4000 字符，笔记 HTML 32768 字符，1000 条操作状态；每次最多 6 次 Notes 调用，每次 15 秒，无自动重试，0 次模型调用。单条模拟运行目标 <1 秒，真实延迟待测。回执只显示末尾 3000 字符并说明截断。

验收：模拟飞书启动、关联回复、暂停/恢复、重复投递、重启；Notes 创建/追加响应丢失、冲突、读回错误、容量和位置校验；真实验证复用先前授权的合成笔记，不创建正式 OKR 数据、不发送真实飞书消息。执行完整检查与模拟演示，区分已实现、模拟和真实证据。
