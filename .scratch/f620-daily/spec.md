# F620/T01 每日日度DOPL自动询问

2026-10-07；依赖F612 b2af817与现有F614/T04。仅一个已注册DOPL、一个既有本人白名单会话；复用OpenClaw command cron每分钟调用插件operator.admin RPC personal-gtd.review.tick，由插件用真实当前时钟判断已确认HH:mm/Asia/Shanghai；不通过模型/主Agent或Codex心跳。RPC不接受伪造时间、身份或文本。没有用户确认时刻不启用生产cron。
公开测试接口：openFeishuCapture.tickReview/handle/recover → 外部飞书消息及Notes；仅替换外部API和时钟。插件RPC和实际host command job另验证。
配置review.daily={enabled,time:HH:mm,senderId,conversationId}；目标严格在既有白名单，read/write权限和Review模块立即检查。状态/设置/暂停/恢复：小婕 review 查询自动询问、设置自动询问 HH:mm、暂停自动询问、恢复自动询问、核对自动询问。控制只接受配置本人/会话的可信新消息；设置立即作用下一次触发，不改变旧问题绑定。
只发与记录心得相同的三个问题，显示日期及稳定询问编号。回复该消息直接独立append原文、真实回复时间戳、读回，自动触发无Notes写。手动/自动共用同一会话：有任何未完成问题/草案或待核对Notes写不新问；手动可明确新开替代旧问，旧回复失效；当天已手动/自动问过则不再自动问。未答复跨日只保留一个问题，不催促/不堆积，不补造心得；回答沿用提问日期/年度（跨年须已有明确年度ID）。
每个日期最多一次发送意图，先SQLite FULL/WAL持久化，再发飞书；重投/重启/改时刻/暂停恢复不重发。时刻后只允许同日本地30分钟窗口补跑；超窗跳过，不补跑过去日；暂停错过时刻恢复也不补跑，下一完整时刻生效。首次启用/改时刻在窗口内仅从新设置后到达时刻允许。宕机在已授权时刻后30分钟内可补一次。
发送超时/响应丢失/读回失败为unknown：下一tick仅一次只读核对既有会话2页各50条及60分钟范围，以询问编号+完整文本+应用发送者定位；唯一匹配安装可信回复关联，未找到/多匹配不重放，停止自动核对，后续用户可显式核对。部分成功保持问题与发送意图，绝不盲重发。成功需真实message_id/chat/text的读回。
预算：每次0模型，最多1发送+1读回；核对最多2列表页、0发送；Notes沿用8桥接/120秒，年度65536纯文/131072HTML；自动运行日志1000日期封顶（不删除未知）；单tick180秒宿主上限，不重叠由现有队列执行，队列16。调度性能实测；飞书/Notes真实闭环另记录。
验收：逐项TDD含日期/时刻/午夜/跨年、重复/重启、未知发送前后、部分成功、未回应、手动关联、撤权、暂停恢复/配置版本、有界核对与容量；旧三模块完整回归。真实启用时刻需用户输入，测试通知先给具体正文及次数；缺输入不阻碍代码/部署/普通推送。

失败准备：当日Notes读取/提问准备失败持久blocked，不每分钟重复尝试。注册查询也展示当前日度启停/时刻和待核对发送。
