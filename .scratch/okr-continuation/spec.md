# OKR 持续讨论回复修复

基准：6147004。用户要求回复原对话持续质询到目标清晰，采用 grilling。

证据：两条失败消息的飞书原消息 API 均返回 updated=true，更新时间比创建时间晚111/271ms；原代码统一拒绝 updated 消息，外层只给通用未确认提示。运行状态无对应来源、模型分析或待写入。这解释错误，但不推断飞书为何设置 updated。

范围：只对已绑定的同用户、同会话 OKR 普通讨论回复，在可信事件正文与 API 当前正文完全一致时允许继续；确认/暂停/显式指令及普通收集仍保持编辑保护。已处理同ID不同正文不得重新执行。正文不一致提示重新发送当前内容，不调用模型或写 Apple。

grilling：一个决定可以讨论多轮，未澄清不自动推进；已有事实、未决问题随检查点恢复，反向审视后仍需用户确认。用户要求重置测试目标作为讨论决定保留，不将测试目标当个人承诺；不在此任务删除历史。

测试接口沿用 openFeishuCapture.handle、openOkrSession.handle、createPlugin 的既有公开接口。合成测试覆盖 updated 回复、旧回执连续15轮、重启、重投、不一致、同ID改文、跨用户及不进入 Inbox。真实失败消息仅只读核验，私人原文不提交。真实模型检查最多2次（首次直连超时后已定位代理配置，第二次经代理验证），在已有55次/$0.5预算内；不自动向飞书发送消息。Native Notes 写入仅恢复用户本次要求的同一讨论，不新增笔记。
